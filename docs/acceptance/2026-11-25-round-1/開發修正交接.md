# WayToGo 功能驗收與開發修正交接

**驗收日期**　2026-11-25（臺北）　｜　**規格**　PRD / SRS v1.0　｜　**對象**　接手修正與回歸驗證的開發 agent

本機工作樹可展示兩位旅伴從邀請、共編行程、投票，到記帳與還款的流程。履歷連結要能讓面試官取得與展示相符的版本，討論頁也要能讓五位旅伴看到彼此的最新編輯。另有兩個 P0 需要處理，分別是原始景點移除失敗與真人 Google 首登受阻。這份交接以原驗收紀錄為基準，列出重現方式、待釐清的原因與修正後的判定條件。[原始驗收報告](功能驗收報告.html) · [規格快照](evidence/system/spec-reference.md)

## 建議處理順序

| 順序 | 接手工作 | 完成時應交得出的證據 |

| 4 | 處理夏令時間、可存取性、個人資料與邀請重送。展示有裝置相依的功能前，補驗 Web Push 與 Safari。 | 見 D04、D07、D09、D10、D15、D17 的回歸條件。 |

### D01　修復五人討論頁收不到編輯更新

**嚴重程度**　高。**關聯需求與回歸對照**　[FR-COMMENT-03](#req-fr-comment-03)、[PERF-02](#req-perf-02)、[MS4-DONE](#req-ms4-done)、[SUCCESS-03](#req-success-03)、[MS5-DONE](#req-ms5-done)、[VALUE-03](#req-value-03)。

- **重現與觀察**　讓五個獨立 Chrome 身分進入同一旅程的討論頁，以各自登入狀態經 API 同時新增一則留言。五個不同 ID 全數可重讀。由作者編輯第一則後，等待其餘四個真實頁面出現新文字的檢查在 10 秒後逾時。SQLite 與隔離的 Compose／PostgreSQL 17.12 均重現。
- **診斷與修正方向**　SQLite 的堆疊捕捉到 WebSocket 更新路徑同步等待 SQLAlchemy 連線。建議對照交易結束、廣播、各頁重新讀取和 DOM 更新的時間。PostgreSQL 的完整等待鏈仍待確認。雙人 20 次編輯的可見延遲 P95 為 181 ms，五人這次沒有足夠的成功樣本可計算。

- **程式位置**　`backend/app/realtime.py:87`、`backend/app/core.py:102`、`backend/app/decisions.py:535`、`frontend/components/TripDetail.tsx:99`。

**嚴重程度**　高・首登驗證受阻。**關聯需求與回歸對照**　[FR-AUTH-01](#req-fr-auth-01)、[FR-AUTH-04](#req-fr-auth-04)、[MS2-DONE](#req-ms2-done)。

- **重現與觀察**　隔離站缺 Google 設定時回 `503 OIDC_NOT_CONFIGURED`。以合成的 OIDC 回應接入真實資料庫，已驗證 Session 輪替、舊 Session 撤銷及會員資料合併。真人同意與外部回呼尚缺專用 OAuth 設定與測試帳號。
- **診斷與修正方向**　先在受控測試站登記回呼網址並配置測試用 OAuth 應用，由獲授權的使用者完成同意。若真實流程失敗，依實際失敗步驟定位。
- **回歸驗收**　執行兩次獨立流程。新使用者首登後可建立旅程並邀請訪客。已有留言、選票與成員紀錄的訪客升級後仍能存取原資料，舊 Session 失效。證據保留畫面、狀態碼與合成資料筆數，憑證及 Token 遮蔽。
- **程式位置**　`backend/app/auth.py:151`、`backend/app/auth.py:213`、`backend/app/auth.py:240`。

### D15　補驗真實裝置的背景 Web Push

**嚴重程度**　中・外部驗證受阻。**關聯需求與回歸對照**　[FR-NOTIFY-02](#req-fr-notify-02)。
